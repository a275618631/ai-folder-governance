# 1. 概念

AI 資料夾治理是一份檔案整理決策契約，協助 Agent 判斷自己知道什麼、可以改什麼，以及變更後需要什麼證據。

## 核心循環

```text
理解 → 分類 → 規劃 → 必要時詢問 → 執行 → 驗證
```

順序很重要：在理解前移動檔案，可能會破壞原本能解決歧義的證據。

## 重要術語

| 術語 | 意義 |
| --- | --- |
| Target | 使用者明確界定、要檢視的資料夾、資料夾集合或專案工作區。 |
| Inventory | 唯讀記錄，包含路徑、metadata、內容訊號、所有權訊號、連結與相依性。 |
| Canonical source | 對某項用途具有權威性的項目或位置，必須有證據支持。 |
| Reference copy | 有用但指向或衍生自 canonical source 的副本，預設不具權威性。 |
| Change set | 提議的移動、改名、封存或刪除清單，含理由與信心度。 |
| Post-condition | 變更後必須成立的敘述，例如連結仍有效。 |
| Material ambiguity | 答案會改變目標、動作、所有權、來源真實性或風險的未知事項。 |
| No-op | 重跑時不再提出新變更，因為前次結果已穩定。 |

## 核心不變量

這些規則比任何資料夾分類更優先：

1. 內容比檔名更有證據力。
2. 所有權比主題相似度更有證據力。
3. Canonical source 比既有副本更有權威性。
4. 先理解，再移動。
5. 除非變更有明確價值，否則保留現有結構。
6. 不可跨越明確的範圍邊界。
7. 將秘密與憑證視為 black box。
8. 移動或改名前檢查路徑相依性。
9. 不確定就詢問，或維持不動。
10. Scan pass 不等於 organization pass。
11. 完成 inventory 不等於完成執行。
12. 每個變更都要有 change set 與 post-condition 證據，或提供 `NO_CHANGE_NEEDED_PROOF`。
13. 第二次執行應該接近 no-op。

## 框架不替你決定的事

框架不會要求每個人都使用 `active`、`archive` 或 `reference` 等固定資料夾。分類取決於工作內容、提供者能力、存取方式與既有習慣。Agent 應在檢視後探索偏好，只在答案會改變結果時詢問。

## 範圍例子

- 單一資料夾的直接子項整理，是窄範圍目標。
- 每週檢視近期變動資料夾，是增量維護目標。
- 遞迴檢視整個專案樹，是深度目標。
- 文件工作區配對機器 Repository，是專案工作區目標。

開始檢查前必須命名目標；「整理全部」不是安全的範圍。
