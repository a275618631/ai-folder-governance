# End-to-end example: Project Meridian

This fictional example shows a complete evidence-led workflow. The names and content are invented. The proposed folders are not a required taxonomy; they are one result of the evidence and preferences below.

## Scenario

The target is `project-meridian/`. It contains working material, a plan, an SOP, a report, a handoff, a prompt, an index with a stale path, a historical root, and a sensitive configuration directory. The user selects `RECURSIVE_DEEP_ORGANIZE`, chooses `preserve-first`, and allows archive proposals but no deletion.

Read the numbered files in order:

1. [Before tree](01-before-tree.txt)

The workflow demonstrates:

- ambiguous canonical candidates;
- a relative path dependency;
- a secret black box;
- mixed roles in one flat folder;
- partial user approval;
- one blocked item;
- explicit post-conditions;
- a second-run near no-op.

Exact structure depends on evidence and user preferences. An agent must not impose this example's folders on another target.
